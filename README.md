# Cloudflare Workers AI Provider for PELDRUN

A PELDRUN provider package that adds [Cloudflare Workers AI](https://developers.cloudflare.com/workers-ai/) as an LLM backend. Ships a **native** adapter (not just an OpenAI-compatible manifest) so it can discover models, validate connections, and stream tokens against Cloudflare's `/ai/v1` and `/ai/models/search` endpoints directly.

## What this is

This repository produces a PELDRUN **Provider Package** — a `.zip` file that, once installed through the Store → Providers UI, makes Cloudflare Workers AI available as a first-class LLM provider inside PELDRUN.

The package contains:

- `manifest.json` — the provider declaration (identity, connection fields, features, permissions).
- `cloudflare_ai_peldrun/adapter.py` — a native adapter (`CloudflareAIAdapter`) that talks to Cloudflare's OpenAI-compatible surface.
- `requirements.txt` — the isolated dependencies (`openai`, `httpx`).

At install time, PELDRUN builds an isolated virtualenv for this package and runs the adapter inside it. The adapter uses:

- `openai.AsyncOpenAI` for chat completions against `https://api.cloudflare.com/client/v4/accounts/{account_id}/ai/v1/chat/completions`
- `httpx.AsyncClient` for model discovery against `https://api.cloudflare.com/client/v4/accounts/{account_id}/ai/models/search`

Both surfaces require only a Cloudflare **Account ID** and an **API Token**.

## Installation

### Option A — Upload the ZIP

1. Download `cloudflare-ai-<version>.zip` from the [Releases page](https://github.com/peldrun/peldrun-providers/releases) of this repository.
2. Open PELDRUN → **Store** → **Providers** → **Upload Package**.
3. Select the downloaded `.zip`.
4. Leave **"Install dependencies in an isolated venv"** checked.
5. Click **Install Package**.

PELDRUN will:

- Validate the archive (size, path safety, manifest schema).
- Extract the files to `storage/store/providers/cloudflare-ai/versions/<version>/`.
- Create a virtualenv with `openai` and `httpx`.
- Register the provider so it appears in the chat model picker.

### Option B — Install from catalog

If your PELDRUN installation has the official catalog configured (the default), Cloudflare Workers AI will appear in the **Catalog** tab after the next catalog refresh. Click **Install** — no ZIP upload required.

The catalog entry is generated by `scripts/generate_catalog_entry.py` on every release and is attached to the corresponding GitHub Release.

## Configuration

The provider has three connection fields:

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| **Account ID** | `string` | ✅ | 32 lowercase hex characters. Find it via `wrangler whoami` or in the Cloudflare dashboard URL (`dash.cloudflare.com/<account_id>/...`). |
| **API Token** | `password` | ✅ | Create one at [dash.cloudflare.com/profile/api-tokens](https://dash.cloudflare.com/profile/api-tokens) with the **`Workers AI Read`** permission. |
| **Base URL** | `url` | — | **Leave empty.** The adapter computes the endpoint from `account_id` automatically. Override only for advanced proxy setups. |

### Minimal setup

1. **Store → Providers → Cloudflare AI → Configure**
2. Fill in **Account ID** and **API Token**.
3. Click **Create Connection** (the "Set as active" checkbox is on by default).
4. Click **⚡ Test** — should return `✓ Connected — <N> ms`.
5. Open any chat, select **Cloudflare AI** as the provider, pick a model, and send a message.

## Usage

### In the PELDRUN chat

Once a connection is active, Cloudflare Workers AI appears in the model picker. Everything PELDRUN supports for built-in providers works here:

- **Streaming** (token-by-token)
- **Tool calling** (for models that declare it)
- **Vision** (for multimodal models)
- **Reasoning** (for QwQ, R1 Distill, Kimi)
- **Token accounting** and **cost tracking** (per Cloudflare's pricing)

### As a Python module

For programmatic use inside PELDRUN's backend:

```python
from cloudflare_ai_peldrun.adapter import CloudflareAIAdapter
from peldrun.llm.contracts import ConnectionContext

context = ConnectionContext(
    connection_id="test",
    provider_id="cloudflare-ai",
    api_key="<your-token>",
    extra_params={"account_id": "<your-account-id>"},
)
adapter = CloudflareAIAdapter(connection=context)

models = await adapter.discover_models()
print([m["id"] for m in models])
await adapter.close()
```

For actual inference, construct a `ProviderContext` (see `peldrun.llm.contracts`) and call `adapter.generate(request)` or iterate `adapter.stream(request)`.

## Development

### Requirements

- Python **3.12.x** (matches `manifest.runtime.python` and `pyproject.toml`)
- `pip`
- `git` (for the changelog script)

### Setup

```bash
git clone https://github.com/peldrun/peldrun-providers.git
cd peldrun-providers
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
pip install "pytest>=8.0,<9.0"
```

### Available scripts

| Command | Purpose |
|---------|---------|
| `python scripts/validate_manifest.py` | Static validation of `manifest.json` (stdlib-only; runs in CI). |
| `python scripts/update_version.py --check` | Verify every file agrees on the current version. |
| `python scripts/build_package.py --verify` | Build `dist/cloudflare-ai-<version>.zip` and sanity-check it. |
| `python scripts/verify_package.py` | Deep verification of the produced ZIP (mirrors the installer's checks). |
| `python scripts/update_version.py <spec>` | Bump the version everywhere and prepend a CHANGELOG section. |
| `python scripts/changelog.py` | Generate a CHANGELOG section from git commits (Conventional Commits). |
| `python scripts/generate_catalog_entry.py` | Produce `dist/catalog-entry.json` for the store catalog. |
| `python scripts/merge_catalog_entry.py` | Merge the entry into an existing `catalog.json`. |
| `python -m pytest tests -v` | Run the manifest integrity tests (35 tests; 3 skip when `peldrun` is not importable). |

### Commit conventions

This repository uses [Conventional Commits](https://www.conventionalcommits.org/) so the changelog script can classify entries automatically:

```
feat(scope): add Responses API support
fix(stream): handle empty choices chunk
docs: clarify connection setup
perf: cache model discovery per connection
```

`chore`, `test`, `ci`, and `style` commits are skipped by `scripts/changelog.py`.

## Building a release

The full pipeline is automated by `.github/workflows/release.yml` — pushing a `v*` tag triggers it. To release manually:

```bash
# 1. Bump the version everywhere and prepend a CHANGELOG section
python scripts/update_version.py patch

# 2. Review the generated CHANGELOG section, then commit it
$EDITOR CHANGELOG.md

# 3. Build and verify the archive
python scripts/build_package.py --verify
python scripts/verify_package.py

# 4. Generate the catalog entry with the correct download URL
#    Replace <TAG> and <VERSION> with the values from
#    `python -c "import json; print(json.load(open('manifest.json'))['version'])"`
python scripts/generate_catalog_entry.py \
    --download-url "https://github.com/<owner>/<repo>/releases/download/v<TAG>/cloudflare-ai-<VERSION>.zip" \
    --brand-color "#F38020" \
    --icon cloudflare

# 5. Commit and tag
git add -A
git commit -m "chore(release): v1.0.4"
git tag -a v1.0.4 -m "Release v1.0.4"
git push origin main
git push origin v1.0.4   # triggers release.yml
```

The workflow verifies that the tag matches `manifest.json["version"]` and refuses to publish on a mismatch.

## Troubleshooting

### "Account ID is not a valid Cloudflare Account ID"

The Account ID must be exactly 32 lowercase hex characters. Copy it verbatim from the Cloudflare dashboard URL — do not include the protocol or the trailing `/`.

### "Authentication failed: 401"

Your API Token is invalid or lacks the `Workers AI Read` permission. Regenerate it at [dash.cloudflare.com/profile/api-tokens](https://dash.cloudflare.com/profile/api-tokens) and make sure it's scoped to the same account.

### "Authentication failed: 403"

The token is valid but the account does not have Workers AI enabled. Free-tier accounts need the Workers AI product enabled once in the Cloudflare dashboard.

### "Connection refused" or "timeout"

Check:
- Your network can reach `api.cloudflare.com` (port 443).
- If you are behind a corporate proxy, set `HTTPS_PROXY` in PELDRUN's environment.

### "Model discovery returns an empty list"

The token may lack `Workers AI Read` scope. Test with `curl`:

```bash
curl -H "Authorization: Bearer $TOKEN" \
  "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/ai/models/search?per_page=1"
```

A `200` response with a non-empty `result` array means the token works.

### "The adapter never receives a token chunk"

Some models on Cloudflare do not stream. If `validate_connection` succeeds but `stream()` hangs, fall back to non-streaming by sending the request without `stream: true` (PELDRUN handles this automatically via its retry policy).

### "Install fails at venv creation"

Confirm PELDRUN's backend Python is 3.12 (matching `manifest.runtime.python`). Other versions are rejected at install time.
